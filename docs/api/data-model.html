Data model

One meaningful table, three Active Storage tables, and the model logic that surrounds them.

Indexes: index_posts_on_slug (unique), index_posts_on_published, index_posts_on_tags (GIN). Schema version 2026_08_28_120930; the only app migration is CreatePosts, alongside the Active Storage install migration.

Active Storage tables

active_storage_blobs, active_storage_attachments, and active_storage_variant_records come from the stock install migration. Post declares has_one_attached :cover_image, but the current upload flow creates a standalone blob and stores its URL in cover_image_url — so the attachment association is available and currently unused.

Model behaviour

class Post < ApplicationRecord
  has_one_attached :cover_image

  validates :title, presence: true
  validates :body_markdown, presence: true
  validates :slug, presence: true, uniqueness: true

  before_validation :generate_slug, on: :create
  before_save :sync_published_at

  scope :published, -> { where(published: true).order(published_at: :desc) }
  scope :drafts,    -> { where(published: false).order(created_at: :desc) }
  scope :by_tag,    ->(tag) { where("? = ANY(tags)", tag.to_s.downcase) }

  def reading_time_minutes
    [ (body_markdown.to_s.scan(/\S+/).length / 200.0).ceil, 1 ].max
  end
end

Slug generation

On create only, and only when slug is blank: title.parameterize (or "post" if that is empty), then -2, -3… until unique. The uniqueness check excludes the record's own id, and the database unique index is the real guarantee.

Publication timestamp

self.published_at ||= Time.current if published? — set once, kept forever. See Writing & publishing for why.

Reading time

Words (\S+) ÷ 200, rounded up, minimum 1. Markdown syntax counts as words, so code-heavy posts read slightly high.

Serialization is a private method on each controller (serialize_post) — no serializer gem, no jbuilder. tags is always coerced to [] when null.

Seeds

api/db/seeds.rb defines 14 long-form posts with realistic bodies, tags, back-dated published_at values, and covers from api/public/covers/. It is idempotent by title: each entry is looked up with Post.find_or_initialize_by(slug: attributes[:title].parameterize) and re-assigned. Two consequences: re-running seeds overwrites local edits to those posts, and if you rename a seeded post's slug the next seed run recreates the original.

Seeds run automatically on every Docker boot (api/bin/docker-dev-entrypoint) and are verified in bin/ci via db:seed:replant.
