All endpoints

Every route the API exposes, with parameters, auth, response shapes, and copy-pasteable curl.

At a glance

Method Path Auth Purpose
GET/uppublicRails health check — 200 when the app booted
GET/api/v1/postspublicPublished posts, paginated, optional tag filter
GET/api/v1/posts/:slugpublic*One post with its Markdown body (*drafts need admin)

PATCH / PUT/api/v1/posts/:slugadminUpdate a post (also publish/unpublish)

Base URL in development: http://localhost:3000. Everything under /api/v1 speaks JSON; send Content-Type: application/json on writes.

GET /api/v1/posts

Param Type Default Notes
tagstring—Exact match, lowercased; ignored when blank
pageinteger1Invalid or ≤ 0 falls back to 1
per_pageinteger10Clamped to 1…100
curl "http://localhost:3000/api/v1/posts?tag=ruby&page=1&per_page=5"

{
  "posts": [
    {
      "title": "The Boring Parts of a Good Rails Application",
      "slug": "the-boring-parts-of-a-good-rails-application",
      "excerpt": "A reliable Rails codebase is usually built from ...",
      "cover_image_url": "/covers/aurora.svg",
      "tags": ["rails", "architecture"],
      "published": true,
      "published_at": "2026-08-01T09:12:00.000Z",
      "reading_time_minutes": 7
    }
  ],
  "meta": { "page": 1, "per_page": 5, "total": 9, "total_pages": 2 }
}

Drafts are never included. body_markdown is omitted from list responses on purpose.

GET /api/v1/posts/:slug

Returns { "post": { …, "body_markdown": "…" } }. Unknown slug → 404 {"error":"Not found"}. A draft slug also returns 404 unless a valid admin token is present, in which case the full draft is returned.

curl http://localhost:3000/api/v1/posts/a-slugged-post
curl -H "Authorization: Bearer $TOKEN" http://localhost:3000/api/v1/posts/my-draft   # drafts

POST /api/v1/session

curl -X POST http://localhost:3000/api/v1/session \
  -H 'Content-Type: application/json' \
  -d '{"password":"change-me"}'

{ "token": "eyJhbGciOiJIUzI1NiJ9..." }

401 on a wrong password, 400 if password is missing (ParameterMissing), 429 after 10 attempts in 3 minutes.

POST /api/v1/posts

Body must be nested under post. Permitted keys: title, slug, excerpt, body_markdown, cover_image_url, published, tags[]. Anything else is dropped silently.

TOKEN=$(curl -s -X POST http://localhost:3000/api/v1/session \
  -H 'Content-Type: application/json' -d '{"password":"change-me"}' | ruby -rjson -e 'puts JSON.parse(STDIN.read)["token"]')

curl -X POST http://localhost:3000/api/v1/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"post":{"title":"Hello world","body_markdown":"# Hi\n\nBody.","tags":["meta"],"published":false}}'

201 with the detailed post on success. Omitting slug generates one from the title. 422 with {"errors":{...}} when title, body, or slug uniqueness fails. Missing the post wrapper is a 400.

PATCH /api/v1/posts/:slug

Partial updates are fine — this is also how publishing works:

curl -X PATCH http://localhost:3000/api/v1/posts/hello-world \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"post":{"published":true}}'

Changing slug changes the public URL immediately; the old one 404s. Publishing stamps published_at only if it was blank.

DELETE /api/v1/posts/:slug

204 No Content on success, 404 for an unknown slug. Attached upload blobs are not removed.

GET /api/v1/admin/posts

Param Values Result
statusdraftPost.drafts — unpublished, newest created first
statuspublishedPost.published — newest published first
statusanything else / omittedAll posts ordered by created_at DESC

Every item includes body_markdown and updated_at (the public list has neither). No pagination here.

POST /api/v1/uploads

curl -X POST http://localhost:3000/api/v1/uploads \
  -H "Authorization: Bearer $TOKEN" \
  -F file=@cover.png

{ "url": "http://localhost:3000/rails/active_storage/blobs/redirect/<signed-id>/cover.png" }

Multipart only, field name file. See Covers & uploads for the validation rules.

GET /api/v1/tags

{ "tags": [ { "tag": "architecture", "count": 4 }, { "tag": "rails", "count": 6 } ] }

Alphabetical; published posts only; posts with no tags are skipped.

GET /api/v1/profile

The parsed YAML file, returned as-is: name, headline, bio[], avatar_url, location, links[], skills[].

GET /up and GET /feed.xml

/up is the stock Rails health endpoint (200 = booted, 500 = boot error) and is what a container orchestrator would poll. /feed.xml is documented on RSS feed.

Routes are declared in api/config/routes.rb with param: :slug, so :slug — never an id — is the path segment everywhere. Slugs are URL-encoded by the frontend before use.
