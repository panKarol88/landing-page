Errors & status codes

Every status code the API can return, where it comes from, and how the frontend reacts.

Status codes

Code Body Raised by
200resource JSONSuccessful read/update
201{ "post": {…} } or { "url": … }Post create, upload create
204emptyPost delete
400{ "error": "param is missing…" }ActionController::ParameterMissing — e.g. no post wrapper, no password
401{ "error": "Authentication required" }authenticate_admin! with a missing/invalid/expired token
401{ "error": "Invalid password" }Login with a wrong or unset password
404{ "error": "Not found" }ActiveRecord::RecordNotFound — unknown slug, or a draft requested anonymously
422{ "errors": { "title": ["can't be blank"] } }Validation failure on create/update
422{ "error": "File must be an image" } etc.Upload validation (missing file, >5 MB, not an image)
429{ "error": "Too many login attempts" }Login rate limit (10 / 3 min)
500Rails error page/JSONUnhandled exception — most often a missing JWT_SECRET or malformed profile.yml

Where the handling lives

# api/app/controllers/application_controller.rb
rescue_from ActiveRecord::RecordNotFound        -> 404 { error: "Not found" }
rescue_from ActionController::ParameterMissing  -> 400 { error: message }
rescue_from ActiveRecord::RecordInvalid         -> 422 { errors: record.errors.to_hash }

# plus an explicit helper used by create/update:
render_validation_errors(record) -> 422 { errors: ... }

Note the two shapes: a single error string for everything except validation failures, which return an errors hash keyed by attribute. Any new client must handle both.

Draft visibility is a 404, not a 403

post = Post.find_by!(slug: params[:slug])
raise ActiveRecord::RecordNotFound unless post.published? || current_admin?

Deliberate: an anonymous visitor cannot distinguish “does not exist” from “exists but unpublished”, so unreleased slugs stay private.

How the frontend surfaces errors

  • request() in web/src/api/client.ts parses the body, and on a non-2xx throws UnauthorizedError for 401 or new Error(payload.error || "Something went wrong. Please try again.") otherwise.
  • Because it reads only payload.error, a 422 validation hash shows the generic message — per-field messages are visible in the network tab or via curl, not in the UI.
  • UnauthorizedError makes every admin screen clear admin_token and redirect to /admin/login.
  • Network failures (API down, wrong VITE_API_URL) reject in fetch and are shown as the browser's message in the same red panel.

Debugging tips

curl -i http://localhost:3000/up                      # is the app up?
docker compose logs -f api                            # request log with full traces
docker compose exec api bin/rails c                    # inspect records directly
curl -i -X POST http://localhost:3000/api/v1/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"post":{"title":""}}'                          # see the real 422 payload

Development runs with config.consider_all_requests_local = true, so unhandled exceptions return full details rather than a generic 500 page.
