Logging into the dashboard

One password, one form, a 7-day token. Here is exactly how to get in and what to do when you cannot.

Logging in

  1. Start the stack (docker compose up or bin/dev).
  2. Open http://localhost:5173/admin/login.
  3. Enter the value of ADMIN_PASSWORD and submit.
  4. On success the token lands in localStorage.admin_token and you are redirected to /admin — or back to whichever admin URL you originally asked for (location.state.from).

Where the password comes from

How you run it Source of ADMIN_PASSWORD Default
Docker ComposeRoot .env or an inline variable, passed into the api servicechange-me
Native (bin/dev / bin/rails s)api/.env, loaded by dotenv-railsnone — login always fails until you set it
TestsSet to test-password in the integration test setup—

Copy .env.example to .env at the repo root (Docker) or api/.env.example to api/.env (native), then set both ADMIN_PASSWORD and JWT_SECRET. Both files are gitignored.

Changing the password

echo 'ADMIN_PASSWORD=something-long' >> .env
docker compose up -d --force-recreate api

Existing tokens keep working after a password change — they are only tied to JWT_SECRET. To invalidate every session, change JWT_SECRET instead (or as well) and restart.

Rate limiting

SessionController declares rate_limit to: 10, within: 3.minutes, only: :create. The eleventh attempt from the same client inside three minutes returns 429 {"error":"Too many login attempts"}. Rails' rate limiter uses the cache store, which is :memory_store in development — so the counter is per process and resets when the API restarts.

Signing out

Sign out in the admin header removes admin_token and returns you to the login form. The token itself remains valid until it expires; nothing server-side is revoked. Any 401 received while using the dashboard triggers the same local cleanup automatically.

What can go wrong

Symptom Cause Fix
“Invalid password”Wrong password, or ADMIN_PASSWORD is empty/unset (an empty expected value always fails)Set it in .env / api/.env and restart
“Too many login attempts”Rate limit hitWait three minutes or restart the API
Login works, then everything 401sJWT_SECRET changed, or the API restarted with a different oneSign in again
500 on loginJWT_SECRET not set at all — Api::Security.jwt_secret raisesSet JWT_SECRET
Redirected to login immediatelyNo admin_token in this browser profileSign in; the token is per browser, per origin
“Something went wrong” / network errorAPI not running or VITE_API_URL points elsewhereCheck http://localhost:3000/up

Because the login is a single shared secret with no second factor, treat ADMIN_PASSWORD as the whole security model of the write side. Do not reuse it, and never commit it — .env.example is committed, .env is not.
