How the JWT auth works

The token, the guard, the failure modes, and what this scheme deliberately does not do.

Issuing

# api/app/controllers/api/v1/session_controller.rb
password = params.require(:password).to_s
expected = ENV.fetch("ADMIN_PASSWORD", "")
valid = expected.present? &&
  ActiveSupport::SecurityUtils.secure_compare(
    Digest::SHA256.hexdigest(password), Digest::SHA256.hexdigest(expected)
  )
return render json: { error: "Invalid password" }, status: :unauthorized unless valid

payload = { admin: true, exp: 7.days.from_now.to_i }
render json: { token: JWT.encode(payload, Api::Security.jwt_secret, "HS256") }
  • Hashing both sides first makes secure_compare safe for different-length inputs and keeps the comparison constant-time.
  • The payload is minimal: { "admin": true, "exp": <unix ts> }. No identity, no jti, no issued-at, no refresh token.
  • Algorithm is HS256 with JWT_SECRET as the shared key.

Verifying

# api/app/controllers/concerns/admin_authentication.rb
def current_admin?
  token = request.headers["Authorization"].to_s.delete_prefix("Bearer ").strip
  return false if token.blank?

  payload, = JWT.decode(token, jwt_secret, true, { algorithm: "HS256" })
  payload["admin"] == true && payload["exp"].to_i > Time.current.to_i
rescue JWT::DecodeError, JWT::ExpiredSignature, JWT::VerificationError
  false
end

Verification is explicit (true plus a pinned algorithm), so an alg: none token is rejected. The expiry is checked twice — once by the library, once by hand. Any decode failure is swallowed into false, which becomes 401 {"error":"Authentication required"} from authenticate_admin!.

Which endpoints are guarded

Endpoint Guard
POST /api/v1/postsauthenticate_admin!
PATCH/PUT /api/v1/posts/:slugauthenticate_admin!
DELETE /api/v1/posts/:slugauthenticate_admin!
GET /api/v1/admin/postsauthenticate_admin! (whole controller)
POST /api/v1/uploadsauthenticate_admin!
GET /api/v1/posts/:slugPublic, but drafts require current_admin? or they 404
GET /api/v1/posts, /tags, /profile, /feed.xml, /upPublic
POST /api/v1/sessionPublic, rate-limited

The secret

# api/config/initializers/security.rb
module Api
  module Security
    def self.jwt_secret
      ENV.fetch("JWT_SECRET") { raise "JWT_SECRET must be configured before using admin authentication" }
    end
  end
end

There is no fallback and no default: a missing JWT_SECRET raises the first time any auth path is exercised (a 500 on login, not a silent insecure mode). Rotating it invalidates every existing token immediately.

Client side

  • Stored as localStorage.admin_token; sent as Authorization: Bearer <token> by web/src/api/client.ts.
  • UnauthorizedError is thrown for any 401; every admin screen reacts by deleting the token and redirecting to /admin/login.
  • ProtectedAdmin only checks for a non-empty string, so the guard is UX, not security — the API is what actually says no.
  • The token is not refreshed. On day eight you are simply asked to sign in again.

Known limitations

  • No revocation list: a leaked token is valid for up to 7 days unless JWT_SECRET changes.
  • localStorage is script-readable; an XSS bug would expose the token. The site renders only your own Markdown, which keeps that surface small.
  • No CSRF machinery is needed because auth is a header, not a cookie.
  • CORS is limited to the two localhost origins, so a hostile page cannot call the API from a browser with your token — until the allowlist grows.
