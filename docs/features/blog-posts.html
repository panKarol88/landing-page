Writing & publishing

Everything about authoring: the editor, the fields, the slug rules, and exactly what publishing does.

Add a post, step by step

  1. Open http://localhost:5173/admin/login and sign in with ADMIN_PASSWORD.
  2. Click New post (/admin/posts/new).
  3. Type a Title. The Slug field mirrors it (lowercased, non-alphanumerics collapsed to -) until you edit the slug yourself, after which it stops following the title.
  4. Optionally write an Excerpt (shown on cards and in the archive).
  5. Set a Cover image: paste a URL or use Upload cover, which uploads immediately and fills the URL field with the returned link.
  6. Add Tags: type and press Enter or , (blurring the field also commits). Tags are lowercased and de-duplicated client-side; click a chip to remove it.
  7. Write the Markdown body — the right pane previews it live with the same renderer the public site uses.
  8. Save keeps the current published state. Publish saves and makes it public in the same request. On an already-published post the button becomes Unpublish.

Creating redirects the URL to /admin/posts/<slug>/edit, so a second Save updates instead of creating a duplicate.

The publishing mechanism

Publishing is not an endpoint — it is the published flag on a normal update. The model does the rest:

before_save :sync_published_at

def sync_published_at
  self.published_at ||= Time.current if published?
end

scope :published, -> { where(published: true).order(published_at: :desc) }
scope :drafts,    -> { where(published: false).order(created_at: :desc) }

Consequences worth remembering:

  • A draft is invisible everywhere public: excluded from GET /api/v1/posts, 404 on GET /api/v1/posts/:slug for anonymous callers, absent from /feed.xml, and its tags are not counted in the tag cloud.
  • Unpublish → republish keeps the original date, so the archive does not reorder. If you actually want a new date, clear published_at in the console (post.update_columns(published_at: nil)) and publish again.
  • The archive is ordered by published_at DESC; the dashboard's “all” tab is ordered by created_at DESC.

Editing and deleting

The editor loads the post through GET /api/v1/posts/:slug with the token, which is how it can open drafts. Saving sends the full draft as PATCH /api/v1/posts/:slug under the original slug, so renaming a slug works — and immediately breaks the old public URL, since no redirect is kept. Delete lives in the dashboard table behind a window.confirm and calls DELETE /api/v1/posts/:slug.

Dashboard

/admin lists posts with tabs all, draft, published (a ?status= query on /api/v1/admin/posts), showing title, status, updated date, and per-row Publish/Unpublish, Edit, and Delete actions. Any 401 from these calls clears localStorage.admin_token and bounces you to the login screen.

Markdown from your own hand is rendered as-is by react-markdown, which does not execute embedded HTML by default. The RSS feed strips HTML explicitly with Redcarpet's filter_html.
