Covers & uploads

Cover images: either a URL you paste, or a file the API validates by its bytes and stores on disk.

The upload path

Editor "Upload cover" input
  -> FormData { file }
  -> POST /api/v1/uploads   (Authorization: Bearer <token>, multipart)
  -> ActiveStorage::Blob.create_and_upload!
  -> 201 { "url": "http://localhost:3000/rails/active_storage/blobs/redirect/<signed-id>/<filename>" }
  -> written into the post's cover_image_url field

What the API accepts

Magic-byte sniffing

return "image/png"  if header.start_with?("\x89PNG\r\n\x1A\n".b)
return "image/jpeg" if header.start_with?("\xFF\xD8\xFF".b)
return "image/gif"  if header.start_with?("GIF87a", "GIF89a")
return "image/webp" if header.start_with?("RIFF".b) && header.byteslice(8, 4) == "WEBP"
nil

The browser-declared content type is ignored entirely; the stored blob gets the sniffed type. Files shorter than 12 bytes are rejected. SVG is not accepted — it can contain script, and the feature is only meant for raster covers. An integration test uploads an SVG labelled image/png (expects 422) and a 1×1 PNG labelled text/plain (expects 201).

Where files live

  • Development uses the Active Storage local disk service → api/storage/, kept in the named volume api-storage under Docker.
  • Tests write to api/tmp/storage.
  • The returned URL is built with rails_blob_url(blob, host: request.base_url), so it is absolute and points at whatever host served the upload — hard-coding localhost:3000 into post bodies is exactly what this avoids, but it also means URLs saved on one host do not follow you to another.

Cover images without uploading

Paste any URL into Cover image URL. Relative paths are resolved against the API by resolveAssetUrl(), which is how the five bundled SVG covers work:

  • /covers/aurora.svg, /covers/forest.svg, /covers/grid.svg, /covers/sunset.svg — seeded post covers, served from api/public/covers/.
  • /covers/avatar.svg — the About-page avatar referenced from profile.yml.

Deleting a post does not delete its uploaded blob. Orphaned files accumulate in api/storage; clean them from the console or wipe the volume with docker compose down -v.
