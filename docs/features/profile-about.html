Profile & About page

Your name, bio, links, and skills come from one YAML file — no database, no admin screen.

The file

api/config/profile.yml is read on every request to GET /api/v1/profile and returned as JSON verbatim:

name: Karol
headline: Software engineer who enjoys making complex systems feel simple
bio:
  - I am Karol, a software engineer interested in the small decisions that make software pleasant to work with.
  - This is where I write about Ruby, web architecture, testing, and the lessons that come from shipping products.
avatar_url: /covers/avatar.svg
location: Europe
links:
  - label: GitHub
    url: https://github.com/
  - label: LinkedIn
    url: https://www.linkedin.com/
skills:
  - Ruby
  - Rails
  - React
  - PostgreSQL
  - Testing

Where each field shows up

Field Type Used by
namestringAbout heading, avatar alt text, theme headers/heroes
headlinestringAbout subtitle and the hero on /
biolist of stringsAbout page paragraphs (one <p> each; the text is the React key, so keep them distinct)
avatar_urlstringAbout avatar, resolved against the API host if relative
locationstring“Based in …” line on About
linkslist of {label, url}“Find me online”, opened with target="_blank" rel="noreferrer"
skillslist of stringsSkill chips on About

Editing it

  1. Edit api/config/profile.yml.
  2. No restart is needed — the controller calls YAML.load_file per request. Reload the About page.
  3. Keep the keys and shapes: the frontend's Profile type expects all seven fields, and bio, links, skills must be lists.

The endpoint is public and returns the whole file, so nothing private belongs in it. It is also unguarded against a malformed file: broken YAML raises and the About page shows an error state. permitted_classes: [Symbol] is the only extra type allowed by the loader.

Replacing the avatar

Drop a file into api/public/covers/ and point avatar_url at /covers/<file>, or use any absolute URL. There is no image processing in this path — the file is served as-is at its natural size and cropped by CSS (h-32 w-32 object-cover).
