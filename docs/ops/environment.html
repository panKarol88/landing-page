Environment variables

Every variable the app reads, its default, and where to set it.

The complete list

ADMIN_PASSWORDSessionController#createnone (""); Compose passes change-meEmpty means every login attempt fails
JWT_SECRETApi::Security.jwt_secretnone; Compose passes local-development-jwt-secret-change-meUnset raises → 500 on any auth path; changing it invalidates all tokens

Context File Committed?

# ./.env  (root, used by docker compose)
ADMIN_PASSWORD=change-me
JWT_SECRET=local-development-jwt-secret-change-me
SITE_URL=http://localhost:5173
VITE_API_URL=http://localhost:3000

Notes that bite

  • Vite variables are compile-time. Changing VITE_API_URL requires restarting the dev server (or rebuilding); it is not read at runtime by the browser.
  • dotenv-rails only loads in development and test. A production run must get real environment variables.
  • Rotating JWT_SECRET is the logout button. It is the only way to invalidate issued tokens.
  • Generate secrets, do not invent them: ruby -rsecurerandom -e 'puts SecureRandom.hex(64)'.
  • Filtered from logs: filter_parameter_logging.rb redacts passw, secret, token, _key, crypt, salt, certificate, otp, ssn, and cvv patterns, so the login password does not land in log/development.log.
  • CORS is not an env var. The allowed origins are hard-coded in api/config/initializers/cors.rb; a new frontend origin means a code change.
