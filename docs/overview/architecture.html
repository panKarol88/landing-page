Architecture

Three processes, one database, one HTTP boundary. Everything interesting happens across that boundary.

The pieces

Piece Where Runs as Responsibility
PostgreSQL 16docker-compose.yml service dbContainer, volume db-dataStores posts and Active Storage tables
Rails 8.1 APIapi/Puma on port 3000JSON API, JWT issuing, uploads, RSS
React SPAweb/Vite dev server on port 5173All rendering, routing, Markdown, themes, admin UI

The frontend never touches the database and the API never renders HTML (except the RSS XML). The only contract between them is JSON over fetch, defined in one file: web/src/api/client.ts.

Reading a public page

Browser -> Vite (index.html + bundle)
        -> GET  http://localhost:3000/api/v1/profile      (About/Hero data)
        -> GET  http://localhost:3000/api/v1/posts?page=1 (published only)
        -> GET  http://localhost:3000/api/v1/tags         (tag cloud)
Markdown is rendered client-side by react-markdown.

The home page fires those three requests in a single Promise.all (web/src/pages/Home.tsx); the blog index fires posts and tags in parallel and re-fires them when the tag or page query parameter changes.

Writing a post

POST /api/v1/session   { password }         -> { token }   (stored in localStorage.admin_token)
GET  /api/v1/admin/posts?status=all         Bearer token   -> drafts + published
POST /api/v1/uploads   multipart file       Bearer token   -> { url }
POST /api/v1/posts     { post: {...} }      Bearer token   -> 201 { post }
PATCH /api/v1/posts/:slug { post: {...} }   Bearer token   -> 200 { post }

Trust boundaries

  • The API is authoritative. authenticate_admin! runs as a before_action on every write (create, update, destroy), on /api/v1/uploads, and on the whole admin posts controller.
  • The frontend guard is cosmetic. ProtectedAdmin in web/src/main.tsx only checks that localStorage.admin_token is non-empty. Faking that value gets you the admin screens, but every request they make comes back 401.
  • Drafts are invisible, not forbidden. GET /api/v1/posts/:slug raises RecordNotFound for an unpublished post unless the caller is an admin, so an anonymous visitor gets 404 rather than 403 — the existence of a draft slug is not leaked.
  • CORS is pinned. api/config/initializers/cors.rb allows only http://localhost:5173 and http://127.0.0.1:5173. Any other origin is rejected by the browser, which is the first thing to change when the site gets a real domain.

Where state lives

State Home Lifetime
Posts, tags, publication datesPostgreSQL posts rowUntil deleted; docker compose down -v wipes it
Uploaded cover imagesActive Storage disk service, api/storage/ (volume api-storage)Until the volume is removed
Admin sessionlocalStorage.admin_token (browser)7 days, or until JWT_SECRET changes
Chosen themelocalStorage.theme (browser)Until changed
Profile textapi/config/profile.yml in gitUntil edited

There is no server-side session store, no Redis, and no background job actually in use: solid_queue, solid_cache, and solid_cable ship with the Rails 8 skeleton but nothing enqueues work.
