Recipes

Copy-paste answers to the things you will actually do.

Start and stop

docker compose up --build       # start (first run / after dependency changes)
docker compose up -d            # start detached
docker compose logs -f api      # watch the API
docker compose down             # stop, keep data
docker compose down -v          # stop and wipe database + uploads

Publish a post from the browser

  1. http://localhost:5173/admin/login → enter ADMIN_PASSWORD.
  2. New post, fill title/body, add tags, optionally upload a cover.
  3. Publish. It appears at /blog, in /feed.xml, and in the tag cloud.

Publish a post from the terminal

TOKEN=$(curl -s -X POST http://localhost:3000/api/v1/session \
  -H 'Content-Type: application/json' -d '{"password":"change-me"}' \
  | ruby -rjson -e 'puts JSON.parse(STDIN.read)["token"]')

curl -s -X POST http://localhost:3000/api/v1/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"post":{"title":"Notes on X","body_markdown":"## Heading\n\nText.","tags":["notes"],"published":true}}'

Unpublish, rename, delete

# unpublish (keeps the original published_at)
curl -X PATCH http://localhost:3000/api/v1/posts/notes-on-x \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"post":{"published":false}}'

# rename the slug (old URL stops working, no redirect)
curl -X PATCH http://localhost:3000/api/v1/posts/notes-on-x \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"post":{"slug":"notes-on-y"}}'

# delete
curl -X DELETE http://localhost:3000/api/v1/posts/notes-on-y -H "Authorization: Bearer $TOKEN"

Force a new publication date

docker compose exec api bin/rails runner \
  'p = Post.find_by!(slug: "notes-on-x"); p.update_columns(published_at: nil); p.update!(published: true)'

Needed because published_at is never overwritten once set.

Bulk-edit tags

docker compose exec api bin/rails runner \
  'Post.where("? = ANY(tags)", "ruby").each { |p| p.update!(tags: p.tags.map { |t| t == "ruby" ? "rails" : t }.uniq) }'

Change the admin password

printf 'ADMIN_PASSWORD=%s\n' 'a-long-passphrase' >> .env
docker compose up -d --force-recreate api      # existing tokens still valid

Log every session out

printf 'JWT_SECRET=%s\n' "$(ruby -rsecurerandom -e 'puts SecureRandom.hex(64)')" >> .env
docker compose up -d --force-recreate api

Edit your profile

$EDITOR api/config/profile.yml     # no restart needed, reload /about

Add a theme

Four touch points: web/src/themes/<id>/index.tsx, a [data-theme="<id>"] block in web/src/styles/themes.css, the registry (THEME_IDS, THEME_LABELS, registry), and both theme-colour lists (ThemeProvider.tsx and the bootstrap script in web/index.html). Details on Four themes.

Add an API endpoint

  1. Declare it inside the api/v1 namespace in config/routes.rb.
  2. Add the controller under app/controllers/api/v1/; inherit ApplicationController so the error mapping applies.
  3. Add before_action :authenticate_admin! if it writes anything.
  4. Add a method to web/src/api/client.ts and a type to web/src/types.ts.
  5. Cover it in api/test/integration/api_test.rb — including the unauthenticated case.

Inspect the database

docker compose exec db psql -U postgres api_development -c \
  'select slug, published, published_at, tags from posts order by created_at desc limit 10;'

Back up and restore

docker compose exec -T db pg_dump -U postgres api_development > backup.sql
docker compose exec -T db psql -U postgres api_development < backup.sql
tar -czf uploads.tgz -C api storage        # cover images

Run every check

docker compose exec api bin/ci                 # style + security + tests + seeds
docker compose exec web npm run lint
docker compose exec web npm run build          # also type-checks

xdg-open docs/index.html      # Linux
